# RFC-0006: MCP execution gateway for IGP

**Status:** Draft, local mock profile, September 2026.

This profile carries the existing runtime `Intent` and signed `ExecutionContract` across an MCP tool boundary. It uses the official MCP TypeScript SDK over stdio. The MCP tool argument to `request_ec2_termination` is an untrusted proposal, normalized by the gateway to `Intent { id, type: "ec2:TerminateInstances", kind: "MUTATION", payload: { instanceIds, skipOsShutdown }, metadata: { actor, timestamp } }`. The gateway supplies the ID, actor, timestamp and kind. The caller supplies `instanceId`, `skipOsShutdown`, optional reason and optional memory. Reason and memory are recorded as untrusted evidence only; neither is an approval record. Tool annotations, descriptions and retrieved text carry no authority.

`request_ec2_termination` returns `structuredContent` matching `schemas/mcp-gateway.schema.json#/$defs/decision`. An allowed decision includes the existing HMAC signed execution contract as `grant`. The contract authenticates its ID, proposal ID, actor, action, intent hash, validity interval, capability and precondition links, and `policyVersion`; the latter is `version@sha256(canonical policy document)`. The HMAC key remains in the gateway. The agent can read the grant but cannot alter authenticated fields. The admitted normalized intent and contract are also retained in IEEC.

`execute_ec2_termination` takes `grant` plus `actual { instanceId, skipOsShutdown }`. Before reaching the adapter, the gateway checks exact operation, target and parameters against the recorded intent; contract equality against IEEC; HMAC and validity bounds; the authoritative policy revision; current context against the admission snapshot; and the reservation state. An atomic `ExecutionStarted` IEEC transition consumes the grant once. Rejected attempts emit `ExecutionRejected` without consuming a still valid grant. An adapter attempt produces `ExecutionCompleted`. The gateway rechecks policy and context immediately before adapter invocation. This is the boundary between admission and execution. A prior admission alone never permits an adapter call.

The random `contractId` is the grant nonce. The IEEC reservation and atomic transition are its replay ledger; a second redemption cannot transition the same proposal from `RESERVED` to `RUNNING`. The local state guard compares the trusted mock instance context that was captured at admission. Because that context is part of the policy document in this profile, a changed state also changes the policy revision.

MCP argument schemas reject unknown fields. The policy document requires `protocolVersion: 1`; other versions and malformed documents fail closed as `POLICY_UNAVAILABLE`. The runtime intent schema remains `schemas/execution-intent.schema.json`. The grant uses `schemas/execution-contract.schema.json`, extended with an optional authenticated policy version for older contract compatibility. This MCP profile requires that field. Decisions and execution results have the JSON Schema definitions in `schemas/mcp-gateway.schema.json`. Denial or remediation is returned as a structured MCP tool result with `isError: true`; a valid allowed decision uses `isError: false`. Invalid MCP arguments are rejected by the SDK. Semantic codes include `POLICY_DENIED`, `ASSURANCE_REQUIRED`, `POLICY_UNAVAILABLE`, `POLICY_VERSION_CONFLICT`, `STATE_GUARD_FAILED`, `OPERATION_MISMATCH`, `GRANT_MISMATCH`, `GRANT_REPLAY`, and `CONTRACT_TEMPORAL_BOUNDS_ERROR`.

MCP protocol negotiation and unsupported MCP versions are handled by the SDK handshake, before any gateway tool handler runs. This profile does not add a second wire envelope or negotiate its own action version.

The authoritative local policy is a file read on every admission and redemption. Writers replace it atomically. Both gateways observe the next revision on their next operation; there is no push and no claim of instantaneous global revocation. If a read or validation fails, destructive operations are denied, including redemption of prior grants. Each operation compares a content hashed revision; changing content without changing the human version still invalidates old grants. A change between the final read and the adapter call is a remaining local race. A production controller needs authenticated distribution and an enforcement fence or short lease to bound that race across hosts.

Conformance example: `npm run demo:mcp` starts two official SDK clients and gateway processes, calls both tool phases, checks denials, substitution, replay and shared policy update, then reads IEEC replay. The output must report `allowed: "executed"`, `protected: "denied"`, `changedTarget: "OPERATION_MISMATCH"`, `oldGrant: "POLICY_VERSION_CONFLICT"`, and `evidence.valid: true`.
