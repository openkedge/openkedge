# RFC-0006: MCP execution gateway for IGP

**Status:** Draft, local mock profile, September 2026.

This profile carries the existing runtime `Intent` and signed `ExecutionContract` across an MCP tool boundary. It uses the official MCP TypeScript SDK over stdio. The MCP tool argument to `request_ec2_termination` is an untrusted proposal, normalized by the gateway to `Intent { id, type: "ec2:TerminateInstances", kind: "MUTATION", payload: { instanceIds, skipOsShutdown }, metadata: { actor, delegatedBy, gatewayId, timestamp } }`. The gateway supplies the ID, actor, delegator, gateway ID, timestamp and kind from trusted launcher configuration. The caller supplies `instanceId`, `skipOsShutdown`, optional reason and optional memory. Reason and memory appear under `metadata.untrustedInputs` with `trustClassification: "UNTRUSTED_AGENT_INPUT"` in IEEC and replay; neither is an approval record. Tool annotations, descriptions and retrieved text carry no authority.

## Stdio identity and secret boundary

Ordinary startup requires `OKG_SIGNING_KEY_HEX` (32 random bytes encoded as 64 hex characters), `OKG_GATEWAY_ID`, `OKG_CALLER_ID`, and `OKG_DELEGATED_BY`. Missing, malformed, weak, or known demo key configuration fails before the MCP server accepts requests. The fixed key exists only in `src/gateway/demo.ts` and requires its explicit demo-only setting. The launcher must obtain ordinary keys from a CSPRNG and protect the environment and evidence database. Secrets are never included in tool results or logs.

The stdio transport is one child process and one caller. `OKG_CALLER_ID` is the actor in the intent, grant and evidence; `OKG_DELEGATED_BY` is the principal the trusted launcher says delegated the task; `OKG_GATEWAY_ID` identifies the gateway instance. These are launcher attestations, not facts proven by MCP or by the delegating principal. No MCP tool argument can change them. The gateway compares all three against its recorded intent during redemption and replay. It rejects another caller's grant and does not return another caller's replay. `openkedge_policy_status` discloses only gateway ID and active policy revision to this process's single caller. Remote or multi-caller authentication requires a different transport and an authentication layer.

`request_ec2_termination` returns `structuredContent` matching `schemas/mcp-gateway.schema.json#/$defs/decision`. An allowed decision includes the existing HMAC signed execution contract as `grant`. The contract authenticates its ID, proposal ID, actor, action, intent hash, validity interval, capability and precondition links, and `policyVersion`; the latter is `version@sha256(canonical policy document)`. The HMAC key remains in the gateway. The agent can read the grant but cannot alter authenticated fields. The admitted normalized intent and contract are also retained in IEEC.

`execute_ec2_termination` takes `grant` plus `actual { instanceId, skipOsShutdown }`. Before reaching the adapter, the gateway checks exact operation, target and parameters against the recorded intent; contract equality against IEEC; HMAC and validity bounds; the authoritative policy revision; current context against the admission snapshot; and the reservation state. An atomic `ExecutionStarted` IEEC transition consumes the grant once. Rejected attempts emit `ExecutionRejected` without consuming a still valid grant. An adapter attempt produces `ExecutionCompleted`. The gateway rechecks policy and context immediately before adapter invocation. This is the boundary between admission and execution. A prior admission alone never permits an adapter call.

The random `contractId` is the grant nonce. The SQLite IEEC reservation and atomic transition are its replay ledger; reopening the same DB after a process restart does not reset redemption status. Concurrent gateway processes sharing that DB cannot both transition the same proposal from `RESERVED` to `RUNNING`. Separate DBs do not share grants; this profile also binds grants to their issuing gateway ID. The local state guard compares the trusted mock instance context that was captured at admission. Because that context is part of the policy document in this profile, a changed state also changes the policy revision.

MCP argument schemas reject unknown fields. The policy document requires `protocolVersion: 1`; other versions and malformed documents fail closed as `POLICY_UNAVAILABLE`. The runtime intent schema remains `schemas/execution-intent.schema.json`. The grant uses `schemas/execution-contract.schema.json`, extended with an optional authenticated policy version for older contract compatibility. This MCP profile requires that field. Decisions and execution results have the JSON Schema definitions in `schemas/mcp-gateway.schema.json`. Denial or remediation is returned as a structured MCP tool result with `isError: true`; a valid allowed decision uses `isError: false`. Invalid MCP arguments are rejected by the SDK. Semantic codes include `POLICY_DENIED`, `ASSURANCE_REQUIRED`, `POLICY_UNAVAILABLE`, `POLICY_VERSION_CONFLICT`, `STATE_GUARD_FAILED`, `OPERATION_MISMATCH`, `GRANT_MISMATCH`, `GRANT_REPLAY`, `CALLER_MISMATCH`, `GATEWAY_MISMATCH`, `EVIDENCE_ACCESS_DENIED`, `EVIDENCE_UNAVAILABLE`, `OUTCOME_UNCERTAIN`, and `CONTRACT_TEMPORAL_BOUNDS_ERROR`.

Evidence read or write failure before the adapter rejects execution. The one-use `ExecutionStarted` event is committed before invocation. If evidence persistence fails after invocation, the action may have occurred; the gateway returns `status: "uncertain"` and leaves the grant unredeemable until an operator reconciles adapter state and evidence. It does not automatically retry a destructive action.

MCP protocol negotiation and unsupported MCP versions are handled by the SDK handshake, before any gateway tool handler runs. This profile does not add a second wire envelope or negotiate its own action version.

## Optional AWS test-instance pilot

The default adapter remains local mock. A separate `OKG_AWS_PILOT_CONFIG` opts into a single running EC2 instance whose live `OpenKedgePilot=disposable` tag, state, exact account, gateway STS ARN, policy allowlist, grant and actual parameters are checked. The pilot uses the existing execution contract and `AwsIdentityProvider`; no new grant format is defined. It creates a restricted STS session with an exact instance ARN, resource-tag condition and grant time bounds. The agent role must have no direct termination permission and no path to assume the execution role. The gateway role may describe instances and assume only the restricted execution role, and explicitly denies direct termination. This IAM split and the local guard are both needed.

DryRun is the pilot default, recorded as `validated`, with no mutation. Real dispatch requires both a test-account config switch and a separate launcher flag. The gateway repeats policy and live resource checks immediately before DryRun and again immediately before a real call. Successful EC2 API acceptance is recorded with request ID, proposal ID, contract ID and assumed-role ARN; final instance termination is not asserted. An ambiguous timeout is `uncertain`, records no verified success, and consumes the grant. CloudTrail role session name contains the proposal ID, and its request ID can be joined to IEEC's contract and outcome. Stdio still attests only one launcher-configured caller; it does not authenticate a remote client. The functional example's shared launcher environment does not prove OS credential isolation. Direct credentials under another principal, network/API paths, administrator access, modified policies or evidence, and compromised launcher state remain bypasses. See [pilot deployment and test limits](../docs/aws-pilot.md).

The authoritative local policy is a file read on every admission and redemption. Writers replace it atomically. Both gateways observe the next revision on their next operation; there is no push and no claim of instantaneous global revocation. If a read or validation fails, destructive operations are denied, including redemption of prior grants. Each operation compares a content hashed revision; changing content without changing the human version still invalidates old grants. A change between the final read and the adapter call is a remaining local race. A production controller needs authenticated distribution and an enforcement fence or short lease to bound that race across hosts.

Conformance examples: `npm run demo:mcp` starts two official SDK clients and gateway processes, calls both tool phases, checks denials, substitution, replay and shared policy update, then reads IEEC replay. The output must report `allowed: "executed"`, `protected: "denied"`, `changedTarget: "OPERATION_MISMATCH"`, `oldGrant: "POLICY_VERSION_CONFLICT"`, and `evidence.valid: true`. `examples/mcp-external-client.mjs` is a separate SDK client process that discovers the tools, executes one allowed action, receives a denial, and inspects its own evidence.
