# MCP gateway implementation note

The reusable runtime lives under `src/core`: `Intent` and `OpenKedgeEngine` define the existing pipeline; `TemporalGovernance` normalizes intent, checks HMAC capabilities and temporal rules, and reserves a signed `ExecutionContract`; `IdentityManager` records scoped identity use; `InMemoryIEECStore` and `SQLiteIEECStore` serialize hash chained events; `ReplayEngine` verifies the chain. The AWS context, safety evaluator and blast radius estimator supply the existing EC2 policy path. The separate `packages/*` proposal model and OPA/Cedar adapters are earlier surfaces; this gateway uses the runtime `Intent` and existing AWS safety evaluator rather than defining another proposal engine.

The main gap was that `OpenKedgeEngine.process()` admitted and executed in one call. It did not expose a separately redeemable grant, compare actual adapter parameters at a later execution boundary, bind a policy revision, or represent an atomic one use redemption event. This slice adds `policyVersion` to the existing signed contract, `ExecutionStarted` and `ExecutionRejected` to IEEC, a strict MCP mapping, and a file backed versioned policy source. The gateway calls the existing governance, AWS safety, blast radius, identity and replay components. Its local allowlist and `skipOsShutdown` rule are deterministic additions for the mock operation; the policy file also uses the existing temporal rule representation.

The file is the local authority. Both gateway processes reread it for admission and redemption and fail closed on read or validation error. Atomic replacement means a subsequent read observes one complete revision. The content hash catches edits with an unchanged human version. There is no background watch, propagation promise, or cross-host controller. A policy change between the final read and mock adapter call remains possible. A production controller needs authenticated distribution and an execution fence or version lease at the credential and API boundary.

The local mock uses no AWS credentials. The agent process gets the MCP tool and signed grant but no adapter credential. Within this process, the adapter is called only after the checks and IEEC one use transition. A caller with direct AWS credentials, access to the gateway's signing key, write access to its policy file or evidence DB, or the ability to call a separate executor bypasses this local control. An AWS deployment must deny direct `ec2:TerminateInstances` to agents, restrict gateway role credentials and network egress, scope AWS IAM to allowed resources, deploy the gateway behind authenticated access, protect policy and signing keys, and use durable shared evidence plus AWS CloudTrail reconciliation. The repository does not currently prove an STS session policy for this MCP path.
