# MCP gateway implementation note

The reusable runtime lives under `src/core`: `Intent` and `OpenKedgeEngine` define the existing pipeline; `TemporalGovernance` normalizes intent, checks HMAC capabilities and temporal rules, and reserves a signed `ExecutionContract`; `IdentityManager` records scoped identity use; `InMemoryIEECStore` and `SQLiteIEECStore` serialize hash chained events; `ReplayEngine` verifies the chain. The AWS context, safety evaluator and blast radius estimator supply the existing EC2 policy path. The separate `packages/*` proposal model and OPA/Cedar adapters are earlier surfaces; this gateway uses the runtime `Intent` and existing AWS safety evaluator rather than defining another proposal engine.

The main gap was that `OpenKedgeEngine.process()` admitted and executed in one call. It did not expose a separately redeemable grant, compare actual adapter parameters at a later execution boundary, bind a policy revision, or represent an atomic one use redemption event. This slice adds `policyVersion` to the existing signed contract, `ExecutionStarted` and `ExecutionRejected` to IEEC, a strict MCP mapping, and a file backed versioned policy source. The gateway calls the existing governance, AWS safety, blast radius, identity and replay components. Its local allowlist and `skipOsShutdown` rule are deterministic additions for the mock operation; the policy file also uses the existing temporal rule representation.

The file is the local authority. Both gateway processes reread it for admission and redemption and fail closed on read or validation error. Atomic replacement means a subsequent read observes one complete revision. The content hash catches edits with an unchanged human version. There is no background watch, propagation promise, or cross-host controller. A policy change between the final read and mock adapter call remains possible. A production controller needs authenticated distribution and an execution fence or version lease at the credential and API boundary.

The stdio server requires a launcher supplied 32-byte hex signing key, gateway ID, caller ID, and delegating principal. The built-in demo alone supplies a fixed key with an explicit demo-only setting. One process serves one caller through its stdin/stdout pipes. The launcher attests the caller and delegator; stdio itself does not verify a human principal or authenticate remote clients. The caller ID becomes `Intent.metadata.actor` and `ExecutionContract.actorId`; the delegator and gateway ID are also in the intent hash and IEEC. Redemption and replay require the configured claims to match. `openkedge_replay` returns full proposal data, including untrusted reason and memory, only to that configured caller and delegator on the issuing gateway. `openkedge_policy_status` returns only a revision. Tool arguments and annotations cannot modify these claims or constitute an approval.

For the protected action, an unavailable IEEC DB or malformed policy blocks the adapter. SQLite commits `ExecutionStarted` before invocation, so a restart or concurrent redemption against the same DB cannot redeem that grant again. Failure after adapter invocation is an uncertain outcome requiring reconciliation; the gateway cannot make a remote side effect atomic with local evidence. Separate DBs are intentionally separate issuers, and grants are bound to the gateway ID. Protect DB and key file access from the caller.

The local mock uses no AWS credentials. The agent process gets the MCP tool and signed grant but no adapter credential. Within this process, the adapter is called only after the checks and IEEC one use transition. A caller with direct AWS credentials, access to the gateway's signing key, write access to its policy file or evidence DB, control of the launcher environment or stdio pipes, or the ability to call a separate executor bypasses this local control. An AWS deployment must deny direct `ec2:TerminateInstances` to agents, restrict gateway role credentials and network egress, scope AWS IAM to allowed resources, deploy the gateway behind authenticated access, protect policy and signing keys, and use durable shared evidence plus AWS CloudTrail reconciliation. The repository does not currently prove an STS session policy for this MCP path.
