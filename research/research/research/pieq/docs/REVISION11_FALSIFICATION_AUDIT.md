# REVISION 11 — Phase 8 Falsification Audit (adversarial PC pass)

Each attack on the central claims, with the executed evidence and an honest classification.

1. **Could one false telemetry domain produce multiple apparently independent proofs?** Attacked via: shared-domain packing tests (SW), live F3 fold-in on real partition evidence (ν=1), EXP-06 adversarial suite (shared domains/leaves under completion), CN05 live (20/20 deferred). No path found: Φ_phys footprints overlap on fd/ch/as tokens regardless of derivation count, context labels, or completion. **No defect.**
2. **Can deterministic completion incorrectly eliminate the true world?** 480 paired replays: 0 within-assumption true-world refutations; missing-sensor and truncation tests show refutation requires verifier-accepted observations and under-population only retains worlds. BUT: if the TRUSTED rules are unsound (CN11), completion admits what the rules certify — **trusted-assumption violation surface (E2 stratum), not a theorem or implementation defect; newly sharpened: completion removes model-prudence masking. Reported prominently.**
3. **Can a stale snapshot pass after a concurrent physical mutation?** Live CN04–CN06 (60/60 deferrals via version/manifest audits), Rev8 P1.3 seven-boundary tests, physical F8-class not executed physically (disclosed). **No within-scope defect; physical F8 remains an evaluation gap.**
4. **Can the policy registry be omitted or downgraded?** Rev11 change: `temporal_policies=None` now raises without `legacy_temporal_mode_opt_in=True`; missing per-action policy fails closed; stale policy rejected at both SQLite and real-PG boundaries (EXP-08 point 9). **Closed (implementation hardening this revision).**
5. **Can an in-flight operation commit after authorization revocation?** E2 adapters: no (in-transaction epoch check — EXP-08 scenario 3, SQLite tests). E0 Patroni target: YES by contract — post-dispatch revocation cannot reach the target; measured and declared (capability contract; F5 covers only pre-dispatch). **Known, declared tier limitation — not a defect, but a real deployment boundary.**
6. **Can a lost acknowledgment cause a duplicate physical mutation?** E2 adapter: no (op_id PK; idempotent re-presentation; no auto-redispatch — EXP-08 scenarios 10–11). Patroni REST: re-sending failover is a NEW operation (no idempotency key) — PIEQ must not auto-retry; enforced by UNKNOWN retention policy, not by the target. **Declared E0 limitation.**
7. **Can an unmediated database writer bypass the guarantee?** Yes, outside mediation assumptions — physically demonstrated twice on purpose (F9 switchover; EXP-08 superuser) and detected post-hoc by reconciliation. **Trusted-assumption boundary (E6), correctly classified, never claimed protected.**
8. **Could native Patroni explain the observed promotions without PIEQ?** EXP-07A: no — paused mode plus observer timelines show no writable primary existed before earliest possible dispatch in any audited trial. Conversely, P1 shows a deterministic supervisor reaches the same F1 decision: the paper claims causal attribution of dispatch, **not** that PIEQ is necessary for promotion, and attributes split-brain prevention to Patroni. **Claim correctly scoped.**
9. **Could single-agent equivalence be benchmark saturation or low power?** Partially plausible: heldout36 actionable cases are at ceiling (9/9) for all conditions, which limits discrimination; EXP-09's repeated runs add variance information but 5 repetitions cannot resolve small differences. The manuscript's claim is therefore limited to "no measurable benefit on this benchmark, with reported uncertainty," and the theoretical claim never depended on it. **Empirical limitation, explicitly stated.**
10. **Could improved live success come from oracle leakage, prompt tuning, or post-hoc case selection?** Completion consumes only authenticated registered evidence + pre-existing rules (code-audited; adversarial-tested); C3 feedback is computable from the agent's own public vocabulary and authorized handles; prompts/cases/labels were hash-frozen before EXP-05/06 and unchanged after results; the failed Rev10 primary run and the EXP-06 prereg-letter violation are preserved, not re-labeled. **No leakage path found; the strongest counter-evidence is that results got *worse* where honesty required (CN11).**
